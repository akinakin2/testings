PODS = Smallest unit in K$b
Abstraction over container
usually one application per pod
each POD get its own virtual IP address

Complications: after a POD dies, a new IP address is attached to the container

SERVICE is introduced to solve this complications. It has a static IP address. and the Lifecycle of POD and SERVICE are not connected BUT PODS USES SERVICES TO COMMUNICATE

External service [People wants to access the application] fixing IP with Port number is not acceptable

INGRESS - resolve the Ip and port to a beautiful web name like www.google.com etc

CONFIGMAP:	Assume my-app need to pull from a database [s3, Mango-db], Database url is usually in the built application:
RE-BUILD > PUSH IT TO REPO > PULL IT IN THE POD

ConfigMap is a configuration file that is connected to POD and has your database url.
if you change the database URL or username or password, NO NEED TO REBUILD THE POD ONLY adjust the ConfigMap with the new URL.

ConfigMap is for non confidential data only and its to be kept secretly.

SECRETE is like a ConfigMap but its used to store secrete data CREDENTIALS bot stored in a 36 bit test format
it is referenced in Deployment /Pod

VOLUMES - Data storage, if Pod is restarted, the data will be gone, Volume is either attached to local machine at a remote, outside of the k8s cluster to safe guide the database after restart or shutdown

NOTE: K8 does not manage data persistence, I MUST DO THAT

## Deployment.yaml

apiVersion: apps/v1
kind: Deployment	(deployment has its metadata and spec section)
metadata:
  name: my-app	(editable)
  labels:
    app: my-app (editable)
spec:		(deployment specific specification)
  replicas: 3	(how many pod you want to create using template/blueprints section)
  selector:	(this help k8 to know which pod goes to where)
    matchLabels:
      app: my-app
  template:	(Blueprint for pods/config for pod)
    metadata:	(has its own 'metadata' n "spec" section)
      labels:
        app: my-app
    spec:	(inside template spec is where we have container config)
      containers:
      - name: my-app	(editable / name of container)
        image: nginx:latest (editable based on where your image is located, either on/off line: its tag/version)
        ports:
        - containerPort: 2710	(editable)

        env:	(Remember the info on deployment and service)
        - name: USERNAME
          valueFrom:
            secretKeyRef:
              name: my-secret	(name of secret.yaml file created)
              key: username
        - name: PASSWORD
          valueFrom:
            secretKeyRef:
              name: my-secret	(name of secret.yaml file created)
              key: password
----
## service.yaml

apiVersion: v1
kind: Service
metadata:
  name: my-app-service
spec:
  selector:
    app: my-app (editable and must align with deployment selector label)
  ports:
  - protocol: TCP
    port: 2710	   (editable to any desired but best practice is to set to container port)
    targetPort: 2710 (editable, must be the same with the port of the container)
  type: LoadBalancer	(for multiple replicas)

## WEB APP

apiVersion: apps/v1
kind: Deployment
metadata:
  name: web-app-deployment (editable)
  labels:
    app: web-app	(editable)
spec:
  replicas: 1
  selector:
    matchLabels:
      app: web-app	(editable)
  template:
    metadata:
      labels:
        app: web-app	(editable)
    spec:
      containers:
      - name: web-app	(editable)
        image: nginx:latest	(editable, use correct image of the web image you want to use, image path, with tag)
        ports:
        - containerPort: 3000	(editable, must be the same with the service.yaml targetPort)
        env:
        - name: USERNAME
          valueFrom:
            secretKeyRef:
              name: my-secret
              key: username	(editable to refence what you used in the secret.yaml, e.g. DB-username, APP_USERNAME etc)
        - name: PASSWORD
          valueFrom:
            secretKeyRef:
              name: my-secret
              key: password	(editable to refence what you used in the secret.yaml, e.g. password, DB-Password, APP_Password etc)

        - name: DB_URL	(editable to desired, REFERENCING CONFIGMAP)
          valueFrom:
            configMaKeyRef:
              name: DB-config	(name supplied in configMap.yaml file)
              key: DB-url	(name supplied in configMap.yaml file)

apiVersion: v1
kind: Service
metadata:
  name: web-app-service	(editable)
spec:
  Type: NodePort	(external access / web site access)
  selector:
    app: web-app	(editable)
  ports:
  - protocol: TCP
    port: 3000
    targetPort: 3000	(editable, must be the same with the deployment container port)
    nodePort: 8080	(this is the port at which it will be assessed from web-site e.g. https:site/IP:8080)
  type: LoadBalancer
